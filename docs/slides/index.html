Deliverable 1 · Problem statement

Farms are checked by hand, so problems are found too late

Problem

Small farms in Cambodia are checked by hand. Dry soil, heat stress in a chicken house or an empty feeder are found too late: crop loss, sick animals, wasted water and feed, long hours.

Solution

Sensors in crop beds, greenhouses and chicken houses; rules that start pumps, fans, heaters, misters and feeders by themselves; alerts to farm staff; schedules; reports.

Core value

Response in seconds, not hours · fewer losses · lower workload · decisions based on data

Small farms are still checked by hand, so problems like dry soil, heat stress or an empty feeder are found too late. Our solution: sensors watch each zone, rules react automatically, and staff are alerted within seconds.

Deliverable 2 · In the code

Permissions are checked on the server

Every write operation calls AccessPolicy.require with the roles allowed to do it.

OOP pillar 1 · Encapsulation

The actuator protects its own state

status is private. Nobody can set it directly.

The only way to change it is through methods like activate, which check the rules first.

A pump can never be started twice, or run longer than its safety limit.

Encapsulation: the actuator's status is private. It only changes through methods like activate, which first check that the actuator is idle and the duration is within its safety limit.

New · Sensor state machine

A broken sensor can be repaired

ONLINE ⇄ OFFLINE follows the signal: a sensor that stops sending comes back by itself.

FAULT: readings ignored, rules paused, so a stuck probe cannot run a pump all night.

MAINTENANCE → ONLINE only after a valid reading since the repair began.

New this week: sensors got their own state machine, the counterpart of the actuator's. Online and offline follow the signal, so a sensor whose cable was fixed comes back by itself. A technician can report a sensor faulty: its readings are then ignored and its rules paused. In maintenance readings are stored again for testing, and completing the repair only works if a valid reading arrived after the repair began.

New · Keeping a temperature

A fixed 5-minute run is not enough

Before: above 34 °C the fan blows 5 minutes and stops, even if the house is still hot. Below 20 °C the heater does the same. Runs too short or too long, and fan and heater can take turns.

Now, like a thermostat: each rule has a stop at value. The fan runs until the house is back to 29 °C; the minutes are only a safety limit.

Interlock: fan and heater never run together. Conflict check: rules that would fight are refused.

above 32 °C

fan starts

29 °C

fan stops

21 – 29 °C

21 °C

heater stops

below 18 °C

heater starts

The problem the user raised: if the fan rule above 34 degrees and the heater rule below 20 each just run for five minutes, the run is the wrong length and the two can conflict. Best practice for holding a temperature is hysteresis, like a thermostat: start at one value, stop at another inside the comfortable band. The chicken house default is fan from 32 down to 29, heater from 18 up to 21, leaving a quiet band of 21 to 29 degrees. On top of that an interlock guarantees fan and heater never run together, and the server refuses rules whose bands overlap.
